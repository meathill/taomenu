# TaoMenu 设计系统与移动端交互基线

- 文档状态：MVP 设计基线
- 版本：0.2
- 更新日期：2026-07-27
- 对应产品文档：[PRD](./PRD.md)

## 1. 设计结论

TaoMenu 采用“越南漆红 + 暖金 + 米纸色”作为品牌识别，再从越南盾聚合物纸币中提取翡翠绿、靛蓝、紫棕和红棕作为辅助色。

不把整个产品做成大红色：

- 红色很适合营销站、Logo、顾客端主 CTA 和升级页，有本地识别度且容易与餐饮联想。
- 店主和员工端是长时间、高压力的操作界面，主操作改用更安静的深翡翠绿，让红色保留品牌识别，也避免与取消/错误语义全部混在一起。
- 纸币色只用于辅助层级、图表、语言标签和菜单分类，不画纸币纹理、不使用钞票图案，避免让 TaoMenu 看起来像钱包或支付公司。

## 2. 文化与产品依据

- 越南国旗的法定基色是红色和黄色；红色在越南 Tết 语境中也与好运和繁荣相关。
- 越南盾并不是单一绿色货币，常见聚合物纸币横跨蓝/蓝紫、红棕、深绿、紫棕和深蓝等色系。这为多彩辅助色提供了本地联想，但不应将颜色与具体金额语义绑定。
- TaoMenu 不使用国旗五角星、纸币人像或真实钞票细节作为品牌资产，只吸收色彩关系。

## 3. 色彩 token

### 3.1 核心色板

| Token | 色值 | 用途 | 对比要求 |
|---|---|---|---|
| `brand-50` | `#FFF1F0` | 浅红提示背景 | 配 `ink-900` |
| `brand-600` | `#B3262D` | Logo、营销 CTA、顾客购物车主按钮 | 配白字，对比度 6.50:1 |
| `brand-700` | `#8C1D24` | 红色按下/深色状态 | 配白字，对比度 9.07:1 |
| `gold-600` | `#C58A12` | 新订单强调、数字徽标、装饰线 | 只配 `ink-900`，不配白字 |
| `paper-50` | `#FFF9F2` | 全局暖白背景 | 配 `ink-900`，对比度 16.39:1 |
| `ink-900` | `#211A18` | 正文、价格、桌号 | 主文字色 |
| `jade-600` | `#2E6F5E` | 店主/员工端主操作、已完成 | 配白字，对比度 5.91:1 |
| `indigo-600` | `#3E5E8C` | 信息、语言、同步状态 | 配白字，对比度 6.59:1 |
| `violet-600` | `#79557A` | 多语言/翻译标签 | 配白字，对比度 6.19:1 |
| `terracotta-600` | `#9B5A3C` | 菜单分类、温暖的次要强调 | 配白字，对比度 5.36:1 |

所有正文与背景至少达到 WCAG 2.2 AA 的 4.5:1；重要图标和控件边界至少 3:1。状态必须同时有文字/图标，不以颜色作为唯一信号。参考 [W3C WCAG 2.2 对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum) 与 [颜色使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color)。

### 3.2 色彩分工

| 场景 | 主色 | 说明 |
|---|---|---|
| 营销站/定价页 | 漆红 + 暖金 + 米纸 | 建立越南本地感和记忆点 |
| 顾客菜单 | 米纸 + 漆红 CTA | 以菜品和价格为主，红色只出现在选中和下单动作 |
| 店主后台 | 米纸 + 翡翠绿 | 长时间使用，操作安静、可信 |
| 员工工作台 | 米纸 + 翡翠绿，新事件用暖金 | 红色只用于已超时或破坏性操作 |
| AI/Pro | 靛蓝 + 紫棕 | 与基础手工功能区分，但不使用炫光渐变 |

## 4. 字体、数字与排版

- 应用端优先使用系统无衬线字体栈，降低越南 4G 首屏成本，并保证越南语声调符号清晰。
- 正文最小 16px；表单 label 14px/600；主按钮 16px/700；员工端桌号至少 28px/700。
- 价格、桌号、订单号使用 tabular numerals，减少列表抖动。
- VND 按 `vi-VN` 格式展示，例如 `149.000 ₫`；数据库仍保存整数 `149000`。
- 布局使用 4px 基础单位，常用间距 8/12/16/24/32px；卡片圆角 16px，输入框/按钮圆角 12px。

## 5. 移动端交互原则

1. **一屏一决定。** 不把桌面后台压缩成手机小字表格；主操作固定在底部拇指区。
2. **主触控目标默认 48×48px。** 可见按钮不小于 44×44px，相邻高频按钮保留至少 8px 间隔。
3. **先展示结果，再给设置。** 员工端卡片首先显示桌号、等待时间、菜品数和主操作；技术连接细节放在营业准备页。
4. **输入有默认。** 记住上次分类、规格和可用状态，价格直接打开数字键盘。
5. **不用颜色猜状态。** 徽标必须显示“新订单”、“已响应”、“已上菜”等越南语文字并配图标。
6. **弱网不假装成功。** 未获得服务端确认前显示“正在发送”；断网只读时清楚标记最后同步时间。

## 6. 三端关键页面

### 6.1 顾客端

- 首屏固定显示餐厅名和桌号，不用全屏品牌海报阻塞菜单。
- 分类横向滚动，菜品以文字和价格为先，图片延迟加载。
- 底部固定购物车/金额按钮；“呼叫服务员”和“请求结账”放入明显但次要的“需要帮助”底部抽屉。
- 提交前再显示餐厅、桌号、明细和总价，避免扫错桌码。
- 取餐订单完成页将取餐号作为最大信息，其次才是订单状态和明细；并明确告知“请留意店员叫号”。
- 顾客可放心切到其他 App。页面返回前台时自动刷新，同时提供明显的“刷新进度”/下拉刷新；不显示“请保持页面打开”，不索要通知权限。

### 6.2 员工端

- 堂食门店底部导航：`订单`、`桌台`、`请求`、`更多`；取餐门店底部导航：`订单`、`取餐`、`菜单`、`更多`。标签使用越南语且不只放图标。
- 新订单卡片的信息层级：桌号 > 等待时间 > 菜品/备注 > 接受按钮。
- 服务请求卡片不与订单卡片混为同一状态；“请求结账”使用账单图标和明确文字，不使用纸币颜色暗示已付款。
- 取餐队列按“新订单 / 制作中 / 可取餐”分组；卡片中取餐号至少 32px/700，主按钮为“可取餐”或“已取餐”。
- 点击“可取餐”或“再次叫号”后，手机显示高对比大号码，供店员一眼看清并口头叫出；不把浏览器 TTS 作为 MVP 依赖。
- 同步/通知故障使用顶部状态条，不用覆盖全屏的技术弹窗阻塞接单。

### 6.3 店主端

- 首次引导是五步任务清单：建店、建菜单、发布、建桌、测试下单；每次只展开当前任务。
- 引导首先询问“顾客在桌边用餐，还是到柜台取餐？”无座店的五步清单将“建桌”替换为“生成取餐码”。
- Free 菜品编辑以“保存并新增下一个”为默认完成动作，并提供复制菜品；Pro 的拍照导入作为独立快捷入口。
- 价格、语言和终端使用卡片展示当前值和下一个动作，不使用宽表格。
- 一键“暂停扫码下单”位于营业状态卡，需二次确认；暂停后按钮改为“恢复接单”。

## 7. AI 和语音界面

- AI 使用靛蓝/紫棕 Pro 标签，但不使用每个按钮都发光的“AI 感”视觉。
- Free 用户点击 Pro 入口先看功能和价值，不在升级前弹相机/麦克风权限。
- 语音是显式按住说话：大按钮、当前转写、停止和取消同屏可见。
- 写操作先展示确认卡：动作、桌号/菜品、数量/金额和原始转写必须同时可核对。
- AI 低置信度不只变黄色，必须显示“需要确认”文字和具体字段。

## 8. 品牌标识建议

- 使用 `TaoMenu` 英文字标，客户界面和营销文案优先越南语。品牌首次出现时可用副句 `Tạo menu. Nhận order.`，但需在本地校对后定稿。
- Logo 图形使用“菜单卡 + 三个 QR 定位角 + 中央 phở 碗与蒸汽 + 右下折角”的简单几何组合；QR 是第一识别层，phở 是越南地域记忆点，不使用筷子、斗笠、灯笼等泛亚洲陈词。
- 应用图标使用漆红、米纸白和翡翠绿，在 48px 下仍可识别，不在图标内放文字；实际门店二维码仍由产品单独生成，不使用品牌 icon 承载订单数据。
- 品牌资产和使用规范见 [TaoMenu 品牌标识](./BRAND.md)。

## 9. 设计验收清单

- 360px 窄屏无水平滚动，软键盘不遮住主提交按钮。
- 顾客、店主和员工三端的主任务可单手完成。
- 所有常规正文对比度至少 4.5:1，重要图标/控件至少 3:1。
- 切换为灰度后仍能通过文字、图标、边框和位置区分订单状态。
- 越南语最长文案和声调符号不被截断，按钮不依赖英文短词长度。
- `149.000 ₫`、`1.490.000 ₫` 等大数金额在窄屏不换行、不溢出。
- 新订单、服务请求、断线、Push 失效和 AI 低置信度都有文字和图标状态。
- 取餐号在阳光下、繁忙柜台和 360px 手机上仍能一眼读出；取餐顾客不会遇到通知权限弹窗。
